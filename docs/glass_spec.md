# S5.6 玻璃与透明度规格

**任务**：S5.6 · **负责人**：art-director（林绘澄） · **状态**：已交付，待审批
**范围**：只读 + 本文件。不改代码、不跑 UE、不 commit。

`glass_pane` / `stained_glass` 现在归在 `fabric` 族 → 渲染成近白 (178,180,184)，与白灰泥立面
(177.8,178.0,174.0) **几乎同色**（实测 dE2000 仅 **4.3**，亮度差 **0.2/255**），
所以**窗户在白墙上完全消失**。`iron_bars` 归 `metal` 族，
而且被贪婪四边形合并成**整片实心金属板**。窗户是教学楼立面的主要特征，也是「立面可辨」这条
验收的关键，所以这两处必须修。

---

## 0. 结论摘要

**1. 玻璃：建议走「不透明 + 反射/高光」，不要真半透明。** 四条依据，前两条是实测：

- **建筑是空心壳**（实测填充率 20.6% / 21.3%）。真透明会露出**空荡内部与孤立楼板**，
  在大尺度读成「废弃/穿帮」，而不是「装了玻璃」。
- **`iron_bars` 被合并成整片实心板**（下方 §1.3 实测）。同理，玻璃也已是**整块立方体**，
  透视会看到内部背面的空腔。
- 半透明要走 `BLEND_TRANSLUCENT` → 不写深度 → 玻璃之间互相排序错误。本项目按建筑分网格，
  一栋楼几百块玻璃，伪影几乎必然。
- **材质图是冻结的已证形状**，本项目已有 `MaterialExpressionWorldPosition` 导致
  「Default Material will be used in game」且日志无因的前科。不透明玻璃**零新节点**。

**2. `iron_bars`：必须是 alpha 镂空的金属，不是实心板**——因为几何已经是实心立方体，
只有 alpha 切洞才能出「栏杆」观感。（改几何=改 mesher，代价更大，不建议。）

**3. 若要 alpha，只用 `BLEND_MASKED`，绝不用 `BLEND_TRANSLUCENT`。** Masked 走
**不透明通道**（写深度、和实体一起排序），因此**完全没有排序伪影**——这是本规格最重要的一条技术判断。

**4. 新增 2 个族（`glass`、`bars`）正好用满图集 24 格**，见 §3 的硬上限。

**5. 优先级：同意 team-lead——颜色变体优先。** 但理由要修正：**不透明深色玻璃本身就是一个
「颜色变体」，和 21 个变体共用同一套烘焙机制**，几乎零边际成本，建议**搭车一起做**；
真正的新工作是 `bars` 的 alpha 路径，那部分排在后面。详见 §6。

### 1.2 `iron_bars` 的 4.65× 差异是口径问题，而且它很重要

`names` 表里 `minecraft:iron_bars` **只有一个字符串**，但有**多个 nameid 指向它**
（我在 metal 族内按 nameid 拆开时，它出现为 2,096 + 1,827 + 1,180 + 1,151 + … 多条）。
按名字聚合后总数是 **8,161**。任务书的 1,754 应该是只统计了其中一部分 nameid（或只算了
暴露在表面的那些）。

**为什么这个差异要紧**：`metal` 族总共 20,232 块，其中 `iron_bars` **8,161 = 40%**。
它是 metal 族里**第一大**成分（超过 `iron_block` 的 3,561）。所以「铁栏」不是边角料，
它决定 metal 族一半的观感。

**同时注意**：`metal` 族里还有 `iron_block` 3,561（必须保持不透明）和
`end_rod` 约 5,139 / `sea_lantern` 1,242（发光体）。**`iron_bars` 不能和它们共用一个
blend mode**，这是 §3 分族的直接原因。

### 1.3 「窗户」是真的窗户——有空间证据

| | 中位数「离地高度」 | 高于 y=24 的比例 | 1–20 格离地窗口带内 |
|---|---|---|---|
| `glass_pane` | **23 格** | **57%** | 40% |
| `glass` | — | **87%** | — |
| `iron_bars` | 17 格 | 43% | **61%** |

`glass_pane` 中位数离地 23 格、57% 在高处，且 `glass_pane` 的分布是**规整重复的**
（多个 16 格区块各含 102 块，位于 d1≈32）——**这是立面上的窗格阵列**，不是地面物件。
结论：玻璃确实主要是**窗户**，`iron_bars` 则**兼有**地面栏杆（57% 在 y≤24）与高处窗栅（43%）。

### 1.4 建筑是空心壳（决定「能不能透视」）

| 结构 | 方块数 | bbox | 填充率 |
|---|---|---|---|
| 结构 25 | 36,716 | 83×37×58 | **20.6%** |
| 结构 28 | 36,519 | 93×40×46 | **21.3%** |

实体建筑应为 100%。20% 说明是**墙 + 楼板 + 屋顶的壳**，内部中空。所以**透视会看到内部
空腔与孤立楼板**。这一条直接否掉了「真半透明更像玻璃」的直觉——在教学楼立面上，
你会透过窗户看到一栋**空的**楼。

> **`iron_bars` 现在被合并成整片实心金属板。**

这是本任务最具体的缺陷，也说明修复路径不必重新发明——**把既有元数据接回管线**即可。

## 2. 目标观感

### 2.1 `glass_pane` / `stained_glass` —— 建议【不透明 + 反射】

**要什么效果**：窗户在白灰泥立面上必须是**深色矩形**，让立面读出「有窗格」的节奏；
近看能读出一条柔和的镜面高光。

**为什么不做半透明**（回答「哪种更可信」）：

| 方案 | UE 里可信度 | 失败模式 |
|---|---|---|
| **不透明深色 + 低粗糙度** ✅ | 高 | 无。这是绝大多数游戏远景窗户的做法 |
| Masked 透视 | 中 | 露出**空心内部**（§1.4）、内部背面；alpha test 无 early-Z |
| Translucent 真半透明 | 低 | **排序伪影**（不写深度）；一栋楼几百格玻璃互相穿插；额外半透明开销 |

「能看到对面与内部」在教学楼上是**负收益**：§1.4 实测内部是空的，透过去会看到一栋空楼，
读成 bug 而不是玻璃。用户要的是「一眼认得出是窗户」，不是物理正确的玻璃。

**具体参数：**

| 参数 | 值 | 说明 |
|---|---|---|
| BaseColor 均值 | **(58, 68, 74)**，可接受区间 (50,60,68)–(70,80,88) | 冷灰蓝。R−B ≈ **−16**（冷），饱和度约 21% |
| 为什么是这个量级 | 与白灰泥 (177.8,178.0,174.0) 形成强对比 | 窗户才「跳」得出来。现在玻璃=白墙，所以窗户消失 |
| 与 `water`(58,106,128) 的区别 | **必须比水灰得多** | water 是 R−B=−70 的强冷蓝；玻璃是**灰玻璃**，不是蓝水 |
| Roughness | **0.10**（区间 0.08–0.15） | **这一项是「看起来像玻璃」的关键**，且是免费参数（见 §4） |
| Metallic | 0（默认） | 不用改 |
| Specular | 默认 0.5 | 不动（改它要加节点，不值得） |
| 贴图内容 | 深底色 + 极弱的竖向渐变 + 每格 1 条细分隔线（窗棂） | 1 格 = 1 次重复，所以重复线就是窗棂阵列 |
| 染色变体 | `glass_white`(233,236,236) / `glass_black`(20,21,25) / `glass_red`(161,39,34) / `glass_orange`(240,118,19) / `glass_light_gray` ← 沿用 `docs/colour_variants.md` 的实机色 | 1,198 块，低优先 |

> **注意 `glass_white` 是反直觉的一项**：白玻璃若用近白 (233,236,236)，在**白墙**上依然会消失。
> 建议 `glass_white` 走**乳白玻璃**（~205,208,206）而不是纯白羊毛色，并靠窗棂线读出窗格。
> 这是我与颜色变体表唯一的偏离，理由就是「别让白玻璃退回白墙」。

### 2.2 `iron_bars` —— 建议【alpha 镂空的金属格栅】

**要什么效果**：读成**栏杆/窗栅**——能看到格子间隙透出背后，不是一块金属板。

**为什么必须用 alpha 而不是细长实体**：几何现在已经是**整块立方体**
（§1.5，greedy quads 合并成片）。要做「细长实体」必须改 mesher，让它对 `non_cube`
方块收缩到细杆——那是几何管线改动，风险和验证成本都远高于一张带 alpha 的贴图。
**贴图 alpha 是唯一不动几何的做法。**

**具体参数：**

| 参数 | 值 |
|---|---|
| BlendMode | **`BLEND_MASKED`** |
| OpacityMaskClipValue | **0.333**（默认值即可，不用调） |
| BaseColor 均值 | **(78, 80, 82)** 深铁灰（当前 metal 族是 120,122,125，对铁栏偏亮） |
| Roughness | **0.30**（金属半哑光；铁栏不是镜面） |
| 贴图 alpha | 杆件 α=1.0，间隙 α=0.0 |
| **不透明覆盖率** | **30–40%**（低于 25% 太稀疏像消失，高于 45% 又读成板） |
| 图案（1 格 = 1 次重复） | 竖杆：u ≈ 0.25 / 0.75，各宽 ≈ 0.10；横档：v ≈ 0.10 / 0.90，各高 ≈ 0.10 |
| TwoSided | **OFF**（理由见 §4） |

### 2.3 直接回答任务书的三个参数问题

**Opacity 目标值区间**
- **`iron_bars` / `glass_pane` 若用 masked：`OpacityMaskClipValue = 0.333`（默认）**，
  alpha 只写 0 和 1 两个值（二值），**不要写中间灰**。Masked 是**二值**判定：α＜0.333 丢弃、
  α≥0.333 保留。写 0.5 和写 1.0 出来完全一样，所以**中间值没有意义**。
- 若一定要「半透明观感」又不想排序伪影：**不要**降 alpha，改用**降低 BaseColor 亮度**来模拟，
  这正是 §2.1 的做法。
- `BLEND_TRANSLUCENT` 的 Opacity 才是连续值，但**本规格不建议用它**（§2.4）。

**是否需要 `TwoSided`：不需要（当前）。**
理由：mesher 产的是**完整立方体**，六个面都有，从内、从外都能看到正面。
`TwoSided` 只在「面片是单面」时才必须（例如将来把窗格改成薄片）。
而且 `TwoSided` 在 UE 里会带来额外代价（禁用部分剔除与部分光照优化）。
**只有在几何改成薄面片时才打开**——这条写进规格，避免以后凭感觉打开。

**`BLEND_*` 选择：`BLEND_MASKED`。** 不要 `BLEND_TRANSLUCENT`。

**折射/高光怎么最省事：只调 Roughness 标量，别的都不做。**
- 已冻结的图形状里**本来就有** `Constant → Roughness`（见 `import_family_materials.py` 头部约束 2）。
  所以「玻璃要亮的反射」= 把这个常数设成 0.10，**不加任何节点**。
- **不要**做折射（`MP_REFRACTION`）：要 scene color，代价高、且半透明才有效。
- **不要**做 Fresnel 边缘高光：需要新节点类型，正是本项目出过静默编译失败的那类改动。
- 默认 Specular 0.5 配合 Roughness 0.10 已经能给出清晰的窗面高光，够用。

### 2.4 为什么 `BLEND_MASKED` 是安全的那一档

这是本规格最重要的一条技术判断：

| | `BLEND_TRANSLUCENT` | `BLEND_MASKED` |
|---|---|---|
| 渲染通道 | 半透明通道（**后画、不写深度**） | **不透明通道（写深度）** |
| 排序 | **需要，且会错**——几百块玻璃互相穿插 | **不需要**，和墙体一起按深度正确遮挡 |
| 阴影 | 需另处理 | 正常参与 |
| 代价 | 高（overdraw + 半透明光照） | 低（alpha test 无 early-Z） |
| 本规格 | ❌ 不用 | ✅ 用 |

**一句话：masked 用的是「挖洞」而不是「混合」，所以它根本没有排序问题。**

## 3. 材质分族建议

### 3.1 建议新增 2 个族：`glass`、`bars`

| 新族 | 收哪些方块 | BlendMode | Roughness | 目标 BaseColor |
|---|---|---|---|---|
| **`glass`** | `glass_pane` 9,422 + `glass` 244 + 5 个染色变体 | `BLEND_OPAQUE` | 0.10 | (58,68,74) |
| **`bars`** | `iron_bars` 8,161 | **`BLEND_MASKED`** | 0.30 | (78,80,82) |

**为什么必须是新族，不能用 `fabric` / `metal` 的变体：**

1. **Blend mode 是材质级属性。** `iron_bars` 必须 masked，但 `metal` 族里还有
   `iron_block` 3,561（**必须不透明**）、`end_rod`、`sea_lantern`。共用一个材质就等于
   把铁块也变成镂空。
2. **`fabric` 同理必须保持不透明**（羊毛 21,542 块 + 地毯 + 床）。玻璃现在是
   `("glass", "fabric")` 这条**占位规则**（`block_families.py:31` 自己写着
   「placeholder until a glass material lands」）——本规格就是来兑现它的。
3. **Roughness 不同**：玻璃 0.10、铁栏 0.30、羊毛/铁块都要各自的值。族=材质，所以必须分开。

### 3.2 硬上限：图集只剩 **2 个空位**

实测 `tools/build_atlas.py`：

```
FAMILIES = 19 个  +  GENERATED_FAMILIES(other, water) = 2  +  SPORT_FAMILY = 1
ATLAS_FAMILIES = 22 个；cols = 8  →  rows = ceil(22/8) = 3
```

`plan_layout()` 里 `y0 = (rows - 1 - row) * cell + pad` —— **`rows` 一变，所有已有族的
v 坐标全部平移**。

- 22 + 2 = **24** = 8 × 3 → **rows 仍是 3 → 零位移**。✅
- 22 + 3 = 25 → **rows 变 4 → 全部族位移 → 所有网格的 UV 失效**。⚠️

**所以：`glass` 和 `bars` 正好用满。不要再加第 3 个族**，否则要重跑 UV 并重建全部网格。

**染色玻璃必须是「变体」不能是「新族」**：5 个染色玻璃若各占一格 = 22+2+5 = 29 → rows 变 4 → 位移。
变体是从族贴图派生的（`out/families/glass_white.png`），**不占图集格**，所以安全。
这与 `docs/colour_variants.md` 的变体机制一致。

> **一个缓冲条件**：如果 mesher 已切到 `--uv-mode block`（任务 #10 已打通），网格里存的是
> **方块单位 UV**，此时图集怎么排都不影响网格，24 格上限就不再是硬约束。**请工程师确认当前
> `--uv-mode`，再决定要不要守 24**。若仍有任何路径用 atlas UV，就按 24 硬上限办。

## 4. 最小节点清单

**核心结论：只需要 1 条新连线 + 2 个材质属性。不需要任何新节点类型。**

### 必须（`bars` 的 masked 材质）

| # | 项 | 说明 |
|---|---|---|
| 1 | `TextureSampleParameter2D` → BaseColor | **已存在**于已证形状，不动 |
| 2 | **新连线：`TextureSample.A` → `MP_OPACITY`** | 唯一的图形改动。**不新增节点**，只是把已有节点的 A 输出接出来 |
| 3 | 材质属性 `BlendMode = BLEND_MASKED` | 材质设置，不是节点 |
| 4 | 材质属性 `OpacityMaskClipValue = 0.333` | 材质设置，不是节点 |
| 5 | 贴图**必须带 alpha 通道**（RGBA8） | 否则 sampler 的 A 输出恒为 1，**masked 会静默变成不透明**——见 §7 |

### 有更好、没有也行（**建议全不做**）

| 项 | 判断 |
|---|---|
| Fresnel → Emissive 边缘高光 | **不做**。需新节点类型；本项目 `WorldPosition` 有静默编译失败前科 |
| 折射 `MP_REFRACTION` | **不做**。需 scene color，只在半透明有效 |
| `Metallic` / `Specular` 节点 | **不做**。默认 Specular 0.5 + Roughness 0.10 已够 |
| `TwoSided` | **不做**（§2.3 有理由）。将来改薄面片才开 |
| 视差/高度窗棂 | **不做** |

### 为什么「不加新节点类型」是关键的风险控制

本项目已知的失败模式是**加节点 → 静默编译失败 → 引擎用默认材质 → cook 仍报成功**
（`MaterialExpressionWorldPosition` 即前车之鉴；`import_family_materials.py` 已把它写成
禁令）。本规格的 masked 路径**只复用已证形状里的节点**，把变量压到「一条连线」，
因此不会引入新的编译路径。

另外请沿用既有的**每步编译校验 + 失败不保存**的约定：编译失败的材质会渲染成引擎棋盘格，
而 cook 不会报错。

## 5. 两档方案

### 保守档（**推荐**）——不需要 alpha

- `glass` 新族，**不透明**，BaseColor (58,68,74)，Roughness 0.10。
- `iron_bars` **暂时留在 `metal`**，或给 `bars` 族但先**不做 alpha**（只换深色 + Roughness 0.30），
  接受它仍是一块板。
- **代价**：铁栏仍读成实心板（8,161 块）。窗户问题 100% 解决。
- **新节点**：0。**新族**：1。**新 shader 变体**：0（仍是不透明）。
- 与 21 个颜色变体**完全同构**，可直接搭车。

### 完整档（**建议随后做**）

- 在保守档基础上，给 `bars` 开 **`BLEND_MASKED`**，贴图带 alpha，镂空成格栅。
- 可选：`glass_pane` 也走 masked（透视），但我**不推荐**（§1.4 空心壳）。
- **代价**：
  - 新增 1 个 masked 材质 = **1 个新 shader 变体**（半透明/遮罩是不同的材质类型）；
  - alpha test **关闭 early-Z**，铁栏区块 overdraw 增加（8,161 块，量不大，可接受）；
  - 遮挡阴影边缘可能出现轻微锯齿（可接受）。
  - **排序伪影：无**（masked 写深度，这是选它的理由）。
- **如果哪天改走 `BLEND_TRANSLUCENT`**：会引入**排序伪影**（不写深度、后画、几百块窗格互相穿插）
  与明显 overdraw 开销。**本规格明确不建议**，除非将来把窗格改成薄面片且只做少量点缀。

**建议节奏**：保守档 → 视觉验收 → 再决定完整档。因为保守档已经解决「立面可辨」的
主要问题（窗户可见），而完整档的收益只在**近距离**铁栏观感。

## 6. 优先级判断

**同意 team-lead 的倾向：颜色变体优先。** 但理由要改一处，因为它影响排期：

| | 颜色变体（21 个） | 玻璃（保守档） | 铁栏 alpha（完整档） |
|---|---|---|---|
| 影响方块 | **194,718（9.99%）** | 9,666（0.50%） | 8,161（0.42%） |
| 修的问题 | **全局色调（整校园偏沙/偏灰）** | 立面窗户可见 | 铁栏观感 |
| 边际成本 | 已在做 | **≈ 一个颜色变体**（同套烘焙机制） | 1 个新 shader 变体 + alpha 管线 |
| 是否新机制 | 否（已有） | **否** | **是** |

**理由（按重要性）**：

1. **量级差 11 倍**（194,718 vs 9,666），且颜色变体修的是**系统性**错误——整个校园的
   沙色/灰色偏，影响每一面墙；玻璃只影响窗。
2. **颜色变体已在飞行中**，而它同时解锁运动场这个点名地标（17,270+9,347+8,852 块）。
3. **但关键修正在这里**：我把玻璃拆成了两件事。**「不透明深色玻璃」本质上就是一个颜色变体**——
   新族 + 一张烘焙贴图 + 一个 gain，**和 21 个变体共用同一套机制、几乎零边际成本**。
   所以它**不该和颜色变体抢排期，应该搭车一起做**。真正独立的新工作是 `bars` 的 alpha 路径，
   那个才需要单独排。**所以顺序是：颜色变体（含不透明玻璃）→ 铁栏 alpha。**
4. 反过来说，如果只看「单位成本换来多少辨识度」，**窗户的杠杆率高于大多数单个颜色变体**：
   一块深色玻璃就能让整面白墙读出窗格节奏。**这是把它并入第一批的理由，不是延后的理由。**

**我唯一想推翻 team-lead 的一点**：不要把「玻璃」整体当作优先级低于颜色变体的事——
把**不透明玻璃**并进颜色变体批次，只把**alpha（铁栏）**放到后面。这样既不增加关键路径，
又能在第一批里就拿到「立面可辨」。

## 7. 会静默失败的点（务必写进实现）

1. **贴图没有 alpha → masked 静默变成不透明。** sampler 的 A 输出恒为 1，`1 ≥ 0.333`
   全部保留，材质看起来「成功」了但没有任何镂空。**必须导入后断言贴图的 alpha 通道存在且有 0 值像素**
   （PNG 级：`min(alpha)==0` 且不透明像素占比在 30–40%）。
2. **Wrap 寻址。** 与 per-family 贴图同理（`import_family_materials.py` 约束 1）：block 单位 UV
   会超过 1，`Clamp` 会把边缘拉满。glass / bars 贴图**必须 Wrap**。
3. **`OpacityMaskClipValue` 被误设成 0** → 全部保留，看起来像不透明；设成 1 → 全部丢弃，
   该族整个**消失**（而且不报错）。**固定 0.333 并断言。**
4. **忘了把 `glass` 规则排在 `fabric` 之前。** 现有 `("glass","fabric")` 是**先命中**的占位规则
   （`block_families.py:31`）。新规则必须插在它**之前**，否则 `glass_pane` 永远拿不到 `glass` 族。
   同时**删掉/改写**那条占位规则，别留两条。
5. **图集格数超 24。** 见 §3.2：第 25 个族会让 `rows` 变 4，平移所有既有族的 v 坐标。
6. **把 `iron_block` 一起染成镂空。** 若用 `metal` 变体而不是新 `bars` 族，容易连带影响
   `iron_block` 3,561 块。用新族可避免。
7. **在 Translucent 上验证。** 如果把材质误设为 `BLEND_TRANSLUCENT`，会因为不写深度出现
   排序伪影，而**单张截图看不出来**（伪影随视角变化）。必须**移动相机**检查，或直接断言
   `BlendMode == BLEND_MASKED`。
8. **`glass_pane` 的几何仍是整块立方体。** 不透明玻璃这样没问题；但如果将来靠 alpha 做透视，
   会看到空心内部（§1.4）。**这不是贴图能解决的**。
